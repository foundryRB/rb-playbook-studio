## Context

A connector-only session synced the toolchain over the per-skill path: enumerate the graph, then `get_skill_files` per skill and `get_agent_files` per agent, writing each file by hand. For the current corpus that is about 84 tool calls and roughly a million tokens, every byte passing through the model twice, and an interrupted run leaves a skill half-written. The work is mechanical: copy what differs and report a table. The client-executes idiom ([ADR-004](../adr-004/)) holds; the cost is in the model doing the copying.

Three facts constrain the shape. The shell that runs a command is not the connector, so it holds no credential, and the command lands in a transcript. The default deployment fronts every path except `/mcp` and `/api/health` with oauth2-proxy for humans ([ADR-006](../adr-006/)). And the playbook already owns an installer, `scripts/install_playbook.py`: where skills and agents land, what a prune may remove, and how each harness spells an agent all live there, and the studio serves agent renderings by loading it.

## Decision

The MCP door offers `get_install_command(runtime)`. It returns one line per shell family: `curl -fsSL '<host>/mcp/install/<token>/install.sh?runtime=<r>' | sh -s --` for POSIX shells, and `& ([scriptblock]::Create((irm '<host>/mcp/install/<token>/install.ps1?runtime=<r>')))` for PowerShell. Flags append to either. It is the one way in: the door serves no install prompt, and its instructions name the tool and no skill.

- **Credential.** The token is minted per call by the door: an HMAC over its expiry with a per-process random key, valid for ten minutes. The gate admits it only on `GET` requests under `/mcp/install/`; it opens no MCP call and no REST route. The connector's Basic credential never appears in the line.
- **Path.** The install routes live under `/mcp/install/`, where machine credentials already pass: oauth2-proxy skips `/mcp`, and the application's own gate admits the token there. No gateway, chart, or platform change is involved.
- **Bundle.** `GET /mcp/install/<token>/bundle.tar.gz?runtime=<r>` returns one gzipped tar laid out so the playbook's installer runs against it as it runs against a clone: a manifest (the harness, a digest over the files, and per file its path, sha256, and executable bit; where each file lands is the installer's to decide), every skill file as its folder's bytes and mode under `skills/`, every agent rendered for that harness by the same renderer `get_agent_files` serves under `agents/`, and the playbook's `install_playbook.py` from the same corpus at `scripts/`.
- **One installer.** The install scripts only find Python 3.8 or newer, download, unpack, and run `scripts/install_playbook.py` from the bundle with the caller's flags. The studio holds no install logic: the comparison by hash and executable bit, the whole-folder swap, the prune, and the summary table are the installer's, the same for a clone and a bundle, and the playbook's own suite attests them.

`get_skill_files` and `get_agent_files` stay, for fetching a single skill or agent.

The install panel on a skill's page in the SPA asks the agent for this same install and names the skill it carries. A skill leans on the skills and agents around it, and the installer writes only what differs, so the panel installs the whole toolchain.

## Rationale

One download and one script turn the sync into a single shell call whose only output the model reads is the table. A minted, download-only token keeps a leaked line worth downloads of the toolchain for ten minutes, where the Basic credential would be worth the whole door. Placing the routes where the machine credential already passes keeps the change inside this repository. Running the playbook's own installer against the bundle leaves one home for every rule a clone install and a connector install share, so the two paths cannot drift.

## Consequences

- The client needs Python 3.8 or newer. The installer imports PyYAML only to render agents from a clone; the bundle carries agents rendered, so a bundle install needs the standard library alone.
- The deployed studio and the playbook it serves move together: the studio loads `scripts/install_playbook.py` from its clone, for agent renderings and for every bundle.
- A token admits any number of downloads until it expires, and dies with the process that minted it; a restart retires every outstanding line, and the caller asks for a fresh one.
- An install from a skill's panel also refreshes every other installed playbook skill and agent that differs from the corpus, a local edit included; an agent that wants that one skill alone fetches it with `get_skill_files`.
- The bundle carries a binary skill asset as its bytes. The per-skill path carries text, so for such a file the two differ; the bundle matches a clone install.

## Alternatives considered and rejected

- **The Basic credential in the command**: publishes the door's long-lived credential into every transcript that runs a sync.
- **Routes under `/api`**: behind oauth2-proxy, so a machine request would need a proxy skip rule in the chart.
- **An applier of the studio's own**: a second home for the write and prune rules, with the facts the playbook's installer keeps inside its `main()` restated beside it and held equal only where a playbook checkout is present.
