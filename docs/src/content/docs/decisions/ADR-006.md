**Status**: Decided
**Supersedes**: [ADR-005](../adr-005/)

## Context

The studio serves interactive browser users and non-interactive MCP clients. The Foundry provisions a per-app Keycloak realm and its client and cookie credentials. The chart defaults to OIDC enabled.

## Decision

With `auth.oidc.enabled: true`, oauth2-proxy fronts the SPA and REST API using the app's Keycloak realm. The application receives `STUDIO_AUTH_SCOPE=mcp`; the proxy bypasses `/mcp` and preserves its Authorization header so the application's HTTP Basic gate authenticates machine clients. The public `/api/health` route is exempt from both gates.

The Basic credentials come from `playbook-studio-auth`; the platform provisions `keycloak-playbook-studio` with `clientSecret` and `cookieSecret` for the proxy. Both are required Kubernetes Secret references: an absent Secret object or a missing referenced OIDC key can prevent the relevant container from starting. This is distinct from a running application with empty Basic credential values: its protected MCP routes return 503.

With OIDC disabled, the application defaults to Basic scope `all`, protecting the SPA, API, and MCP. Empty Basic credential values in a running application return 503 on protected routes. Local composition uses this mode.

## Rationale

OIDC gives browser users the platform's interactive identity flow while MCP clients authenticate through an ordinary HTTP header. Keeping the Basic check in the application preserves the machine door's fail-closed behavior and supports local runs without an identity provider.

## Alternatives considered and rejected

- **Basic across all deployed surfaces**: the shared browser prompt lacks the platform's federated human login.
- **Interactive OIDC on MCP**: machine clients need a non-interactive credential path.
