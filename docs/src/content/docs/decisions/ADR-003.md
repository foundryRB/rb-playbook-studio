**Status**: Decided

## Context

The deployed studio manages a clone it owns and pushes with a repo-scoped credential. The local run edits a sibling checkout that the operator commits with their own tools. Both are the same application.

## Decision

Git behavior (pull, commit, push, status) is an outbound port. The deployed composition wires the real git adapter, authenticated with a fine-grained PAT scoped to the content repo. The local composition points `STUDIO_PLAYBOOK_ROOT` at the sibling checkout and wires a no-op sync adapter. Use cases call the port unconditionally; no code inside the application layer branches on where it runs.

## Rationale

- The capability difference between deployed and local is a wiring decision, decided once in the composition root, exactly like every other adapter choice in the hexagon.
- A no-op adapter keeps the local editing flow identical to what it always was: the studio edits the working tree, the operator owns the commits.
- Use cases stay testable with a fake port; neither environment leaks into application logic.

## Alternatives considered and rejected

- **Mode flags inside use cases** (`if deployed: commit`): scatters the environment across the application layer and multiplies test permutations; the hexagon exists to prevent exactly this.
- **A separate local build without git**: forks the application into two artifacts that drift; one image plus composition wiring keeps a single artifact.
