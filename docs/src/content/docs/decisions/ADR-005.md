**Date**: 2026-07-03
**Status**: Superseded by [ADR-006](../adr-006/)

## Context

The studio manages a private repository and serves on a public hostname. Every surface (SPA, `/api`, `/mcp`) needs gating before the instance serves anything.

## Decision

HTTP Basic auth gates all three surfaces with a single shared credential, fail-closed: the chart names `auth.existingSecret: playbook-studio-auth`, the repo commits `k8s/secrets/playbook-studio-auth.env.example` documenting the keys, and protected routes answer 503 until the Secret is provisioned out of band. Browsers get the native prompt; MCP clients pass the `Authorization` header. Editor attribution rides on commit trailers.

## Rationale

- `playbook` is private; an unauthenticated deployed studio would republish it. Fail-closed means a misconfigured instance is closed, never silently open, which is what makes publishing the hostname safe.
- One mechanism covers all three surfaces; MCP clients speak HTTP and carry headers natively.
- Commit trailers give per-edit attribution without a user model; per-agent identity can arrive later if warranted.

## Alternatives considered and rejected

- **A second auth scheme for MCP** (tokens, OAuth): more machinery for the same single-maintainer trust boundary; headers over Basic already work in every MCP client.
- **Edge-only gating** (tunnel or access proxy in front): leaves the app itself open inside the cluster and couples safety to infrastructure the app cannot verify; the app refusing to serve unauthenticated is self-contained.
