**Status**: Decided

## Context

The machine door takes one shared HTTP Basic credential ([ADR-006](../adr-006/)). Whoever holds it acts with the deployment's full authority, so handing it to a person makes them an admin, and a person who should only read cannot connect an agent at all. People need to connect their own agents as themselves ([ADR-011](../adr-011/)); services that drive the studio unattended still need a credential of their own.

## Decision

- **Minting.** A person signed in on the human door ([ADR-010](../adr-010/)) mints a token with `POST /api/tokens`, from the Connect menu. It is shown once. Every signed-in person may mint one, a reader included: the token carries identity, not rights.
- **Shape.** `pst1.<payload>.<signature>`: the payload names the person (email and display name), the time it was issued and the time it expires; the signature is HMAC-SHA256 over it with `STUDIO_TOKEN_KEY`, a key of 32 bytes or more from the app's Secret. Tokens live 90 days (`STUDIO_TOKEN_TTL_DAYS`).
- **Use.** Any MCP client sends it as `Authorization: Bearer <token>`. On `/mcp` the gate admits a token that verifies, has not expired, and was not issued before the person's `not-before` line in `OWNERS`; the request then acts as that person. A token opens nothing but the machine door.
- **Revocation.** An admin records `not-before <email> <date>` in `OWNERS`; it takes effect on the next request.
- **The shared credential.** HTTP Basic on `/mcp` stays, for services: it acts as the service, whose commits name the service. `/api/agent-credential` hands the pair back only to a caller that already acts as the service (the stand-alone deployment); a person is refused it.
- **No key, no tokens.** Without `STUDIO_TOKEN_KEY`, nothing is minted and no token is admitted; the shared credential still works.

## Rationale

A token signed with a key the deployment holds needs no store: verifying it is a pure function of the token and the key, so it survives a restart and a redeploy, and a stolen one cannot be stretched or re-addressed. Revocation by date fits that design, and putting it in `OWNERS` keeps every rights decision in one reviewed file. Download tokens ([ADR-009](../adr-009/)) keep their per-process key: they live minutes and a restart retiring them is harmless.

## Consequences

- The release needs `STUDIO_TOKEN_KEY` in the app's auth Secret; rotating it retires every outstanding personal token.
- A person removed from the realm keeps a working token until it expires or an admin records a `not-before` line for them; their rights still come from `OWNERS` on every request.

## Alternatives considered and rejected

- **The shared credential for people**: it makes every connected person an admin and every commit the service's.
- **OAuth on the MCP transport**: the clients this door serves configure a static header; an interactive flow per client is not what they support.
- **A token store**: a database for what a signature already proves.
